# Security

Supported version: 0.1.x.

Use the repository host's private vulnerability reporting. Do not open a public issue with secrets or transcript text.

The no-install demo needs Python 3.11+ and downloads nothing from an existing source folder. uv may download an interpreter; pip may download build tools. Installation stays inside your venv. Linux and macOS are supported; native Windows is refused before POSIX imports. State privacy relies on POSIX modes and local filesystem semantics, not Windows ACLs. Use only local session files.

`stop` and `resume` control this watcher, not agent processes. Stopping a watch run terminates its own reviewer or resume-delivery child. No notification hook, service, timer or scheduled task is installed.

Review defaults to OFF and requires explicit consent stored only in your own config. `status` shows the choice. `--dry-run` and `demo` never call a reviewer or delivery CLI. After consent, a review sends a scrubbed digest of one vendor's session to the other vendor through your own CLI. Scrubbing understands sensitive JSON keys, YAML blocks, environment assignments, authentication headers, credential URLs, incomplete private-key blocks, common token prefixes and long opaque strings. Any sensitive or uncertain JSON key withholds the complete review. For free-form sensitive syntax, including shell/header continuations, comments, masked tails and escaped structures, no value endpoint is guessed: the complete review is withheld before calling the vendor. Malformed structures, excessive depth/size and scrub failures also stop reviews with scrub-uncertain. Local display withholds the affected text. Scrubbing precedes length cuts. It can over-redact; unlabelled short secrets in ordinary prose still cannot be identified reliably. Output is scrubbed again before display or logging.

Transcript text is untrusted input. The Claude reviewer disables tools when that flag is supported. The Codex reviewer uses a read-only sandbox, an empty working folder and an ephemeral session when supported. Codex can still read local files within its sandbox; no tool-disable flag was verified. Older CLIs may lack optional safeguards. Shape checks, a bounded digest, nonce delimiters, a strict answer schema and fixed message templates reduce risk; they do not eliminate prompt injection.

Automatic replies keep an agent working with whatever permissions its own session has. Claude resume delivery starts a non-interactive continuation as a child process. Do not enable it for a session open in another window. No permission-bypass mode is enabled by this tool.

Child environments omit `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `OPENAI_API_KEY` and `CODEX_API_KEY`. Other provider or billing arrangements are unsupported. Config and profiles are trusted owner inputs; an executable path can run code. Keep them private and do not load untrusted config files.

Reviewer arguments are fixed; nonempty reviewer `extra_args` are rejected. Delivery extras only accept a single documented permission-mode pair (`default`, `acceptEdits`, or `plan`). Model names cannot be options. Timeouts are capped at 600 seconds for review and 3600 for resume delivery. The following strings are also rejected without regard to case:

- `--bare`
- `--yolo` (a bypass alias)
- `--dangerously-skip-permissions`
- `--allow-dangerously-skip-permissions`
- `bypassPermissions`
- `--dangerously-bypass-approvals-and-sandbox`
- `--dangerously-bypass-hook-trust`
- `danger-full-access`

Automatic delivery accepts only the eight tool-owned templates chosen by a validated ID, with no free-text draft delivered. The sole parameter is a validated index into the trusted profile’s decided list: one ASCII line of at most 200 characters, excluding risky wording, quotes, control characters and message labels. A profile change before delivery blocks the quote. A reviewer can select the wrong recorded decision; the owner must keep that list narrow. Every template requires coherent structured evidence for the latest whole turn: a supported normal terminal event, paired tools with explicit successful outcomes, ordered timestamps after the latest input, and no later activity. Every event is scanned for failures, nonzero exits, denied permissions, interruptions, retries, aborts and pending approvals/questions. Missing or unknown evidence fails closed. Final prose supplies only additional vetoes; success wording cannot grant permission. See [the supported shapes](docs/event-shapes.md). The never-list is an additional heuristic and cannot be removed through config. Replies require explicit per-run opt-in, an allowed folder, live mode and an explicitly enabled delivery adapter. Both delivery adapters default to off. A TURN-STATUS line never authorizes a reply. An append-only, hash-chained attempt journal, checkpoint and independent witness in the fixed HOME config directory supplement transcript marker counts. The witness hash/sequence and filesystem identity block paired state rollback and ordinary byte restoration of all three files. Missing or replaced witnesses block delivery. Wall/monotonic disagreement and backdating block delivery; both elapsed windows must expire before counts age out. Explicit clock recovery preserves lifetime counts and conservatively refreshes rate windows. Missing, corrupt or truncated accounting blocks live sends until an explicit `sidecarwatch rearm`. Attempts are recorded and synced before delivery, including attempts interrupted by a stop. Human transcript messages cannot reset the lifetime session cap. A fixed global 100-attempt cap applies per trailing 24 hours. Re-arming valid files retains counts; explicit recovery preserves damaged files and starts new accounting. This detects ordinary file restoration, accidental loss and partial writes. It cannot detect a coordinated full-machine snapshot restoring filesystem identity and clock state, or deliberate local forgery. Witnesses must be excluded from state backups; intentional machine recovery requires owner inspection and explicit re-arming. Similarity checks and the never-list are heuristics; unusual phrasing can evade them. Quiet-time fallback is for observation only and cannot authorize resumption. A fresh parse before delivery reduces this race but cannot eliminate it.

Run `sidecarwatch stop` to stop reviews and deliveries. Child termination can take up to five additional seconds. Use `log.text="none"` to omit verdict text from state files. State files use private modes. Never submit real sessions, logs or private term lists with a bug report.

A labelled sensitive value anywhere in candidate review input withholds the entire review before vendor or capability calls, including JSON containers and labels decorated with Markdown, table cells, headings, comments, Unicode lookalikes or zero-width characters. Cross-message labels are checked before any input cuts. Local display uses a refusal token; unknown short unlabelled secrets and representations outside the documented recognizer remain residual risks. No universal secret-detection or language-understanding guarantee is claimed.

Invalid Unicode, NUL, excessive string size/depth and malformed marker counters produce visible parse notes and prohibit review/delivery. Worker terminal failures are persisted independently of review eligibility. A deadline observation pass reports unresolved workers without resuming them.
